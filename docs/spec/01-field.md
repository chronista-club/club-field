- 状態: 草案（2026-11-21）。U1 の範囲は実装済み（2026-11-22、設計は [`docs/design/01-field-program.md`](../design/01-field-program.md)）

## What — Chronista Club とは

chronista.club は、人が集まる、リアルタイムのライブ配信の場。
その土台が **field** で、ユーザは自分の field を持つところから始める。

## Why — 決まったこと（mako の裁定、2026-11-21）

| # | 裁定 | 原文 |
|---|---|---|
| 0 | 人が集まる、リアルタイムのライブ配信の場 | 「ここは人が集まる場所。Chronista Club。ここでリアルタイムでのライブ配信のための場所となります。Ladylandのfield、そのものといっていい。ユーザはここにLadylandなり、何かを使って、音と映像の次の表現に向かって進む。」 |
| 1 | 配るのは映像ではなく field の状態。映像はカメラがあるときの追加出力 | 「１は、「場」」「場があって、もし（配信用）カメラがあるなら、映像も届けられる。」 |
| 2 | 来た人は、まず見るだけ | 「まずは見るだけにしておこうか。」 |
| 3 | 小さく始める。サーバ / クライアント / データの視点で組み立てる | 「小さく始めるとして、サーバコンポーネント、クライアントコンポーネント、流れるデータ、そういう視点で構築していこうか。」 |
| 4 | クライアントは一旦考えない | 「一旦clientのことわすれて」 |
| 5 | field はサーバ上にある | 「まずは、フィールドが、サーバ上になくてはいけないね。」 |
| 6 | Ladyland も一旦考えない | 「Ladylandも忘れて良いです。」 |
| 7 | ユーザは自分の field を持つ。手元でもクラウドでも | 「まずはユーザがすること、自分のフィールドを持つ。そしてそれは、手元でもクラウド上でも、持てる。」 |
| 8 | 手元の field とクラウドの field は別々 | 「別々だね。」 |

## ユーザがすること

| # | 行為 | この spec |
|---|---|---|
| U1 | 自分の field を持つ（手元に / クラウドに） | 対象 |
| U2 | field に何かを置く | 対象外 |
| U3 | 人が来て、見る | 「入る」だけ対象。描画は対象外 |

## field の定義（U1）

field 1 つが持つもの:

| 項目 | 内容 |
|---|---|
| 持ち主 | ユーザ 1 人。変わらない |
| 名前 | 持ち主の中で一意 |
| 場所 | 手元 or クラウド。生まれた場所に住み続ける |
| 時計 | 一定間隔の tick。誰もいなくても進む。状態はメモリ上だけなので、立ち上がり直すと 0 に戻る |
| 動いているか | 止まっている間は、入れず、時計も進まない |
| 代 | 何代めか。立ち上がり直すたびに 1 つ増える |

field を指す鍵は「持ち主 + 名前」。止まっても、立ち上がり直しても、同じ field。

## 操作（U1）

| 操作 | 向き | 内容 |
|---|---|---|
| 持つ | ユーザ → 手元 or クラウドの置き場 | field を作る。持ち主・名前・場所が決まる |
| 入る | 外 → field | その時点の状態をすぐ受け取り、以後の tick を受け始める |
| 出ていく | 外 → field | 以後の tick を受け取らなくなる。field はそのまま動き続ける |
| tick | field → 入っている全員 | 時計が 1 つ進み、その時点の状態を知らせとして送り出す |
| 止まる | field | プロセスが止まる。入っていた人は全員外れる |
| 立ち上がり直す | field | 同じ field が、同じ場所で、次の代として動き出す。時計は 0 から |

tick の知らせは、送り出されてから届くまでに時間がかかる。

## tick の道のり（未決）

知らせをどの道で運ぶかで、成り立つ性質と必要な決まりが変わる。**どれにするかは未決**。
モデルは 5 通りを持ち、同じ性質を全部に当てて比べている。

| 道のり | モデル上の名前 | 内容 | unison では |
|---|---|---|---|
| 順不同・上書き | `dgramNaive` | 順番が入れ替わる・失われる。届いたもので上書きする | datagram channel |
| 順不同・古い番号を捨てる | `dgramDiscard` | 同上。受け取る側が、手元より古い番号を捨てる | datagram channel |
| 順不同・古い番号と前の代を捨てる | `dgramDiscardLife` | 同上。さらに、前の代の知らせも捨てる | datagram channel |
| 順番どおり・全部届ける | `streamAll` | 送った順に、欠けずに届く。溜まったぶんも全部届く | stream channel |
| 順番どおり・新しいものだけ | `streamLatest` | 送った順に届く。溜まったら送る側が古いものから捨てる（残すのは 2 つ） | stream channel + 送る側で間引く |

### 比べた結果（2026-11-21）

○ = 成り立つ ／ × = 破れる（反例が見つかる）

| 性質 | モデル上の名前 | 順不同・上書き | 順不同・古い番号を捨てる | 順不同・前の代も捨てる | 順番どおり・全部 | 順番どおり・新しいものだけ |
|---|---|---|---|---|---|---|
| 基本の 6 つ（手元が field より先に進まない、ほか） | `allInvariants` | × | × | ○ | ○ | ○ |
| 手元の tick は戻らない | `seenNeverGoesBack` | × | ○ | ○ | ○ | ○ |
| 途中の知らせがもう無いなら、手元は今の状態と同じ | `quietMeansCurrent` | × | × | × | ○ | ○ |
| 1 人あてに溜まる知らせは 2 つまで | `backlogAtMostTwo` | ×（※） | ×（※） | ×（※） | × | ○ |
| 入っている人は常に今の状態を持っている | `alwaysCurrent` | × | × | × | × | × |

※ 順不同の道では、実際の知らせは届くか消えるかで、溜まり続けはしない。
この行の × はモデル上の数え方によるもので、順番どおりの道の × と同じ意味ではない。

### 検査で見つかった反例

| # | 足したもの | 破れた性質 | 反例の筋 | 対処 |
|---|---|---|---|---|
| 1 | 届くまでの遅れ | 常に今の状態を持っている | 入る → tick。届く前は、手元は 0、field は 1 | 約束しない |
| 2 | 順番の入れ替わり | 手元の tick は戻らない | tick を 2 回 → 2 番めが先に届く → 1 番めが後から届く | 古い番号を捨てる、または順番どおりの道を使う |
| 3 | 知らせが失われる | 途中の知らせが無いなら今の状態と同じ | tick → その知らせが失われる。次の tick まで古いまま | 変化が無くても定期的に送り直す、または順番どおりの道を使う |
| 4 | 止まる・立ち上がり直す | 手元が field より先に進まない | 入る → tick → 止まる → 立ち上がり直す（時計 0）→ 入り直す → 前の代の知らせ（tick 1）が届く。手元は 1、field は 0 | 知らせに代を載せて前の代を捨てる、または順番どおりの道を使う |

反例 4 は、順不同の道だけで起きる。順番どおりの道では、止まると道ごと閉じて途中の知らせも消えるので、起きない。

### 読み取れること

| 道のり | 困ること | 必要になる決まり |
|---|---|---|
| 順不同・上書き | 手元が古い状態に戻る | 使えない |
| 順不同・古い番号を捨てる | 立ち上がり直した後、手元が field より先に進む | 使えない |
| 順不同・前の代も捨てる | 最後の知らせが失われると、次の tick まで古いまま | 知らせに**代・番号・状態**を載せる／古い番号を捨てる／前の代を捨てる／変化が無くても定期的に送り直す |
| 順番どおり・全部 | 受け取りが遅い人は、古い状態を順に全部受け取ることになり、遅れが広がる | 受け取る側の決まりは不要。状態は差分でもよい |
| 順番どおり・新しいものだけ | 送る側で間引くぶん、知らせが欠ける | **知らせに状態を丸ごと載せる**。受け取る側の決まりは不要 |

どの道でも言えること:

- 「入っている人が常に今の状態を持っている」は約束できない
- field が止まると、入っていた人は全員外れる。立ち上がり直したら、入り直す
- 立ち上がり直しても、同じ field（同じ持ち主・名前・場所）

## 守られるべきこと

モデルで確かめている性質。名前は `docs/model/field.qnt` の定義名。

基本の 6 つ（`allInvariants`）:

| 性質 | モデル上の名前 |
|---|---|
| 手元の tick が、field の時計より先に進むことはない | `seenNeverAhead` |
| 途中の知らせが、未来のことを言うことはない | `inflightNeverAhead` |
| field は生まれた場所に住み続ける | `placeNeverChanges` |
| 時計は戻らない（同じ代の中で） | `tickNeverNegative` |
| 存在しない field に入っている人はいない | `noOneInMissingField` |
| 止まっている field に入っている人はいない | `stoppedFieldHasNoOne` |

## 確かめ方

```bash
docs/model/check.sh
```

5 通りの道のりそれぞれで、場面の確かめと、上の比較表の成否を実行し、期待と突き合わせる。
期待と違えば終了コード 1。

個別に見るとき:

```bash
bunx @informalsystems/quint@0.33.1 test docs/model/field.qnt --main=streamLatest
bunx @informalsystems/quint@0.33.1 run  docs/model/field.qnt --main=dgramDiscard --invariant=seenNeverAhead
```

- `test` は場面ごとの確かめ（`run ...Test`）を実行する
- `run` はランダムな操作列を多数試し、性質が破れる例を探す。全状態の網羅ではない。
  つまり表の ○ は「20,000 本の試行で反例が見つからなかった」という意味で、証明ではない

## モデルが単純化していること

| 点 | モデル | 実際 |
|---|---|---|
| 接続が切れる | 自分から出るか、field が止まるか | 黙って切れることもある |
| 止まったことに気づく | 止まった瞬間に全員が外れる | 入っていた側が気づくまでに時間がかかる |
| 立ち上がり直す回数 | 2 回まで | 何度でも |
| 持ち主の確かめ | 無い（名乗ったとおり） | 認可が要る |
| 時間 | 順番だけを扱う | 何ミリ秒遅れるか、は扱っていない |
| 送る側の間引き | 送り出した後でも古いものを捨てられる | stream に書き込んだ後は取り消せない。捨てられるのは書き込む前まで |

これらは、該当する決め事を足すときにモデルへ足す。

## 対象外（この spec では決めない）

field の中身と「置く」操作、クライアントと描画、Ladyland との接続、音、カメラ、
認可、住所（`/@handle`）、クラウドの置き場、複数の演者、記録。
